# Source-backed awaitables and async streams

Research and implementation snapshot: 2026-09-16. This document records the next managed-library slice after the recovered `f87fe22` baseline. It supplements, rather than replaces, the broader [industry](industry-state-2026-09-16.md) and [BCL/runtime](bcl-runtime-2026-09-16.md) research.

## Findings that determine the implementation

Microsoft's async-enumerable design article explains that the compiler-generated iterator can implement enumeration, asynchronous state-machine, and value-task-source interfaces together, with a reusable completion core for advancing and disposing. It is a historical architecture explanation, not a claim that every current compiler emits the exact sample layout. Our actual inputs are PE/CIL generated by the selected SDK. [S1]

The ValueTask API contract distinguishes result, Task and IValueTaskSource representations. Consumers must not treat an arbitrary source-backed value as a freely repeatable Task: multiple awaits/conversions or premature/repeated result consumption can violate its contract. This makes token handling and single consumption observable compiler/library behavior. [S2]

The upstream completion core has versioned operations, completion/continuation state, and scheduling/context machinery. Our implementation deliberately implements its sequential cooperative protocol, not the upstream interlocked, multithreaded or context-flow implementation. No upstream completion-core source is vendored. [S3]

Configured async enumeration forwards its selected cancellation token to GetAsyncEnumerator. Replacing a configuration should replace the selected token, not accumulate unrelated token state. [S4]

ExceptionDispatchInfo in .NET preserves dispatch information beyond the exception object. A portable implementation that only retains identity must disclose that narrower behavior. Our added Capture/SourceException/Throw paths support generated cleanup code; native/managed stack reconstruction and remote stack injection are not supplied. [S5]

## Architectural choice: implement protocols, not source syntax shortcuts

The new code is original C# in Transpiler.Bcl. The existing compiler imports and specializes that assembly alongside the real Roslyn-generated application state machines. Both source backends consume the same method bodies. No async-iterator recognizer was added to bypass the CIL pipeline, and no JavaScript generator body is substituted for a C# method.

The dependency chain is explicit:

```text
IValueTaskSource / ManualResetValueTaskSourceCore
    -> source-backed ValueTask + awaiters + Task conversion
    -> AsyncIteratorMethodBuilder + IAsyncEnumerable/IAsyncEnumerator
    -> configured enumeration + cancellation + IAsyncDisposable
    -> ordinary imported Roslyn iterator/consumer state machines
```

This approach also exposes defects that a syntax-only demonstration could miss. A property read that appears harmless can consume a reusable source. A cleanup method can suspend. Disposal can replace an earlier exception. A canceled source is not interchangeable with any fault that happens to throw OperationCanceledException.

## Completion and consumption invariants

The completion core publishes one result or error per version. Reset changes the short token and clears the previous operation. GetStatus, GetResult and OnCompleted validate the supplied token. A second consumer registration and a second completion are rejected by the implemented sequential checks.

Continuation/state fields are cleared before invoking user code. This permits a completion callback to consume the result, reset the source and register its next operation without a late cleanup write erasing that registration. Requested asynchronous continuations and registration after completion use the existing translated FIFO scheduler. Flags are passed through by awaiters, but that scheduler has no captured ExecutionContext or SynchronizationContext.

The token is a short, not an unbounded generation number. Its value wraps after 65,536 resets. The implementation and edge test preserve that limitation; token equality is not a security or indefinite stale-handle guarantee.

AsTask consumes a source operation through a managed bridge. The bridge releases its source field before publishing Task completion. It uses source status to distinguish cancellation from faults, rather than blindly classifying every OperationCanceledException as canceled. Preserve converts a source-backed value into a repeatable Task-backed representation.

A regression test found that the initial ValueTask<T>.ToString implementation read Result twice. A source which resets during GetResult exposed the second read. ToString now obtains one result and formats that local value. The test observes exactly one consumption.

## Iterator lifetime and cancellation

The portable builder delegates scheduling to the existing state-machine protocol. Enumerator creation, suspension, yielded values, disposal mode and finally paths remain in the imported application IL. Generic and nongeneric value-task-source interfaces support MoveNextAsync and DisposeAsync respectively.

Configured enumeration holds the actual enumerator, selected token and await configuration. The tests exercise both configuration orders, a token captured by the iterator, a distinct token supplied at enumeration, linked cancellation, and cancellation before the first item. Tokens are observed by managed code; they do not forcibly interrupt arbitrary computation.

ExceptionDispatchInfo was a real missing dependency found while compiling awaited cleanup. It is implemented as an identity-preserving managed object, with explicit rejection of unimplemented remote-stack APIs. Awaited finally blocks, early loop exit, nested streams and cleanup-exception replacement have differential tests.

## Validation and boundaries

New fixtures cover ordinary and source-backed values, token invalidation/wraparound, callback flags, completion-before-registration, reentrant reset, async cleanup, independent enumeration, covariance, struct Current copies, explicit faults and cancellation. Both Debug and Release applications run against CoreCLR and both generated languages.

The host protocol test completes a source from a JavaScript yield callback or Python asyncio task. It checks managed-method provenance and that callback/state fields are cleared. The block-emission comparison now includes source-backed values and async streams. These are correctness/size tests, not a throughput or allocation benchmark.

Still outside this slice: concurrent source completion/registration, thread pools, timers, context capture, arbitrary async-LINQ operators, native JS/Python async-generator marshalling, exact .NET exception traces, and complete BCL compatibility. Existing generated Task/ValueTask host invocation is supported; consume a managed stream inside an exported Task method when using that ABI. The [contract](../async-streams.md) and [compatibility ledger](../compatibility.md) are authoritative.
